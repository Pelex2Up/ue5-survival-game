# Совместная работа (команда из 3 человек)

## Принципы

1. **Один ассет — один владелец за раз.** Blueprint и `.uasset` нельзя смержить как код. Если два человека меняют один файл — побеждает последний push, второй теряет работу.
2. **Делим по зонам, не по файлам.** Каждый отвечает за свою папку или фичу на текущий спринт.
3. **Черновики локально, финал в `ProjectSurvival/`.** Песочница `Content/Developers/<имя>/` не коммитится — переносите готовое в общие папки.

## Рекомендуемое разделение (пример)

Назначьте зоны под ваши роли — это шаблон, не жёсткое правило:

| Участник | Зона ответственности | Папки |
|----------|---------------------|-------|
| **A** | Геймплей и системы | `Core/`, `Gameplay/`, `Items/`, `Crafting/` |
| **B** | Персонажи и мир | `Characters/`, `Environment/`, `Maps/` |
| **C** | UI, аудио, VFX | `UI/`, `Audio/`, `VFX/` |

На созвоне раз в неделю сверяйте, кто какую зону занимает, чтобы не пересекаться.

## Workflow

### Начало задачи

```bash
git checkout dev
git pull
git checkout -b feature/краткое-описание
```

### Во время работы

- Создавайте **новые** Blueprint с префиксами:
  - `BP_` — Blueprint Actor
  - `WBP_` — Widget Blueprint
  - `ABP_` — Anim Blueprint
  - `DA_` — Data Asset / Primary Data Asset
  - `DT_` — Data Table
  - `BPI_` — Blueprint Interface
- Имена на **английском**, PascalCase: `BP_PlayerCharacter`, `WBP_InventorySlot`
- Не переименовывайте и не перемещайте чужие ассеты без согласования (ломает ссылки у других)

### Завершение задачи

```bash
git add .
git commit -m "feat: краткое описание"
git push -u origin feature/краткое-описание
```

Создать PR в `dev`. После ревью — merge. Периодически `dev` → `main`.

### Перед каждым сеансом

```bash
git pull
git lfs pull
```

## Работа с картами

- **Prototype/** — каждый может иметь свой тестовый уровень: `Map_Test_Player.uasset`, `Map_Test_Crafting.uasset`
- **Production/** — общие уровни; один человек = один уровень за раз
- Для больших миров используйте **World Partition** и **Data Layers**, чтобы не трогать одни и те же ячейки

## Конфликты

Если `git pull` конфликтует на `.uasset`:

1. Не пытайтесь мержить вручную
2. Согласуйтесь, чья версия актуальнее
3. Один откатывает свой файл: `git checkout --theirs` или `--ours`
4. Второй переносит свои изменения заново в редакторе

## Source Control в редакторе

В Unreal: **Edit → Plugins → Git Source Control** (включить, перезапуск).

Затем **Edit → Project Settings → Plugins → Git** — указать путь к git.

После этого в Content Browser видно, кто изменил ассет.
